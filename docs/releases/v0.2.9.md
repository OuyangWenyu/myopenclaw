# myopenclaw v0.2.9

补丁版本（2026-11-17）。**不改产品行为**，只修一个长期挂账的测试缺陷，并把热备的
行为契约从「宿主工具链」挪到「生产镜像」。镜像、compose、服务配置全部未动 ——
**不需要重建任何镜像或容器**。

## 本版变更

### 修掉 `TestHermesCronDbHotCopy` 的「macOS 假红 / CI 假绿」

自 v0.2.7 起，这条用例在 macOS 上恒红、在 CI 上恒绿，一直被当作「已知 macOS 红」
口头记账（记了三次发版）。根因不是备份脚本，而是**断言测的是读取器的副作用**：

- 用例先用 `sqlite3 <快照副本> "SELECT count(*) …"` 验证数据，再断言「快照里不许有
  `executions.db-wal`」；
- `.backup` 出的副本继承源库的 `journal_mode=wal`，**这次读取**就会在快照目录里
  生成 `-wal`/`-shm`；关闭时清不清理取决于读取器构建 ——
  Apple `/usr/bin/sqlite3` **3.54.0** 保留（0 字节 `-wal` + `-shm`，两次实测都留），
  Ubuntu 24.04 的 **3.45.1**、python libsqlite3 **3.53.4** 会清理。
- 所以红/绿两边都没在测备份脚本：本机假红、CI 假绿，且 GitHub runner 换 sqlite
  版本时 CI 会无故转红。

备份脚本本身是干净的（逐步实测）：`.backup` 只写出 `dest/executions.db.tmp`，`mv`
后快照里只有一个文件；源目录 rsync 也带 `--exclude="executions.db*"`。

修法：

- 验证副本改用 `file:<path>?immutable=1`（不生成任何 sidecar；`-readonly` 反而不行
  —— WAL 库缺 `-shm` 时只读打开直接 CANTOPEN）；
- 断言扩成「快照里**只许有副本本身**」：两个库各查 `-wal`/`-shm`，再查
  `.tmp`/`.tmp-wal`/`.tmp-shm` 无残留（原来只查了一个路径，漏了中间产物）。

### 热备的行为契约搬到生产镜像（Alpine + sqlite 3.45.3）

新增 `TestHermesCronDbHotCopyInContainer`：把同一场景塞进 `backup-cron` 镜像跑，
**种子库和副本校验都用镜像自带的 sqlite**，宿主 `sqlite3` 完全不参与：

1. 容器内造两个种子库（一个 WAL、一个回滚模式）→ 跑 `/hermes-scripts/backup.sh`；
2. 断言快照 `cron/` 里只有 `executions.db` + `notepad.db`；
3. 再起一个容器，`immutable=1` 读副本，断言两条都能读出数据。

宿主用例保留为**快速预检**，容器用例是**契约**。

配套的 CI 与语义（防「静默失效」）：

- `release-checks.yml` 测试前先 `docker build -t myopenclaw-backup-cron:ci
  ./docker/backup-cron`，并把该镜像名通过 `BACKUP_CRON_IMAGE` 传给 pytest；
- `BACKUP_CRON_IMAGE` **未设**（本机没 build）→ 用例 **skip**；**已设但镜像不可用**
  → 用例 **fail**。否则 CI 的 build 步骤哪天坏掉，用例会被 skip 静默吞掉 ——
  正是这次要消灭的模式。

### 测试与文档

- 两处都做了**注入口字验证**：给 `hermes/scripts/backup.sh` 临时加一条
  `: > "${DEST}/cron/notepad.db-wal"`，宿主用例与容器用例各自都红（容器用例直接
  列出三个文件），恢复后绿。
- `docs/backup.md` 补两条：① 生产（`backup-cron`，Alpine sqlite 3.45.3）与测试
  （宿主机 PATH 上的 sqlite）不是同一个，两者**偶然行为**不同；② 新加行为用例请
  照「容器内复跑」的形状写，不要断言宿主工具链的副作用。

## 升级注意

- **不需要**重建镜像、不需要 `docker compose up -d`：本版只有测试、CI、文档变更。
- 想在本机跑容器用例，先建镜像（不建则 skip）：

  ```bash
  docker compose build backup-cron        # 或 docker build -t myopenclaw-backup-cron:latest ./docker/backup-cron
  uv run --with pytest --with pyyaml pytest tests/test_ops_defaults.py -q
  ```

- `hermes` 镜像里**没有** sqlite3 二进制（只有 python 的 libsqlite3），热备脚本只该在
  `backup-cron` 或宿主机手动跑（缺 sqlite3 时 fail-loud，不做 `cp` 兜底）。

## 已知边界

- **macOS 仍然没有 CI**：本版只把「热备」这一条路径的工具链差异收口，其他行为用例若
  出现同类差异，按同样模式处理（先在容器里复跑，再决定是否接受宿主预检）。
- **容器用例依赖 docker**：CI 与有 Docker Desktop 的本机跑得到；无 docker 的机器上
  skip（预检仍覆盖大部分行为）。
- **Apple sqlite 3.54.0 的行为未改变**：本版只是让断言不再依赖它；宿主机上手动
  `./scripts/backup-all.sh` 仍用 Apple sqlite 做热备，产物与容器一致（脚本不读副本）。
