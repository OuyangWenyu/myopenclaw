# Issue 正文模板

每条 intake issue 都用这个骨架。**开头必须是 `## 来源`**（脚本会检查这一行）。

```markdown
## 来源
- 链接：https://example.com/...
- 平台/仓库：some-org/some-repo
- 看到的时间：2026-11-24

## 是什么
2–4 句事实：它做了什么、怎么用、当前状态（活跃/归档/实验性）。
不要复制大段 README，不要写「非常优秀」这类评价。

## 为什么对我们有用
- 对应本仓：<owner/repo> 的 <模块/痛点>
- 可复用的部分：具体到文件/接口/思路
- 预期收益：省掉什么、快多少、补哪个缺口

## 建议做法
1. 先做最小验证（例如：跑通官方 demo，确认输入输出）
2. …
3. …

## 风险 / 成本
- 许可协议（MIT / Apache-2.0 / GPL / 未声明）
- 依赖体积、维护活跃度、与现有栈的冲突
- 若不采用，替代方案是什么

## 验收标准
- [ ] 可验证的一条
- [ ] 再一条

---
> 由道元整理（repo-issue-intake），供人工判断是否排期；未复制第三方代码。
```

## 写作尺度

| 项目 | 要求 |
|---|---|
| 标题 | ≤ 120 字，只写「做什么」；不带「建议/提案」前缀，不带 emoji |
| 正文 | 200–800 字；超过 4KB 就删细节，只留可执行结论 |
| 来源 | 必须可追溯；无外链时写「对话：用户口述」 |
| 代码 | 只放 5–15 行关键片段；不整段拷贝第三方代码 |
| 许可 | 正文提到许可证；不确定就写「未核实」 |
| 语气 | 事实优先；不吹、不贬、不写「颠覆/革命性」 |

## 反例

- 只贴一个链接，正文写「这个可以看看」——没有诉求，无法排期。
- 把 README 整篇贴进来——issue 不是剪藏。
- 写「应该很简单」——没有依据的工期判断。
- 同时给 3 个仓库各写一条同主题 issue——应选主责仓库，其余写进「备选」。
